# 文档索引

这个目录只放**从代码里读不到的东西**：数据集的实测结论、口径解释、以及给答辩/评审用的说明。
接口契约、字段字典、业务规则都住在代码与配置里（`backend/resources/*.yaml`、
`backend/app/pipeline/*.py`），不在这里复制一份——两份必然走样。

| 文件 | 讲什么 | 什么时候看 |
|---|---|---|
| [真实数据体检.md](真实数据体检.md) | 两份真实数据集（DS-01 417 行带性别 / DS-02 11.5 万行无性别）跑完整条管线后的实测结果：行数、去重、单位归一、DQ、耗时、5 个被数据打出来的 bug、人工核对抽样、**答辩能讲/不能讲** 清单 | 想知道"这套东西在真实数据上到底靠不靠谱"时 |
| [../README.md](../README.md) | 一键启动、IDE 里怎么开、目录说明、测试与门禁、改配色/改区间、已实现功能对照、**五条实现与需求文档不一致的地方** | 第一次把项目跑起来时 |
| [../.env.example](../.env.example) | 所有 `CBC_*` 环境变量：数据库、Redis、限额、鉴权、网络 | 要换 Postgres / 部署到别处时 |

## 需求与分析说明书去哪了

《血常规数据分析与可视化系统-需求与分析说明书》（CBC-INSIGHT-SRS-001，v1.6）**不在本仓库**，
它维护在作者的学习笔记库里，随项目推进同步升版本。

不放进仓库的原因很实际：那份文档是**的需求来源**，每次评审都在改（v1.5→v1.6 一轮就动了
180 行）；把它的副本塞进代码库，只会出现"仓库里那份是三周前的"这种状态，而读的人不会
先看提交时间。代码库里只保留**结论**（本文档目录）与**可执行的规则**（YAML + 测试）。

若需要随仓库分发，建议二选一：

1. 发布 release 时把 SRS 导出成 PDF 附在 release assets 里（版本明确、不会被误改）；
2. 单独建一个 `docs/srs/` 并在 README 里写明"以 release 附件为准，仓库内为快照"。

## 需求编号对照

代码与提交信息里出现的 `FR-xx` / `BR-xx` / `T-xx` / `NFR-xx` / `RK-xx` 都指向上面那份 SRS：

- `FR` 功能需求、`BR` 业务规则、`NFR` 非功能需求、`T` 验收用例、`RK` 风险条目；
- 三个编号在实现里被"扩用"过，README 第九章有完整说明：
  `UNCLASSIFIED`（BR-07 兜底模式）、rbc 单位 ÷100（3.4 原文写 ÷1000）、
  BR-03 核心字段豁免、区间 15 项而非 16 项、`has_snapshot` 字段。
